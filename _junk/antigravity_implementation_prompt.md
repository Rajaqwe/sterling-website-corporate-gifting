## Phase 1 — Security & data-integrity (do these first, in this order)

1. **Fix forgeable admin role check.** `src/middleware.ts`, `src/app/(auth)/actions.ts`, and `src/components/layout/Navbar.tsx` currently check `user.user_metadata?.role`, which any logged-in user can edit themselves via the Supabase client SDK. Switch all three to check `user.app_metadata?.role` instead. Add a server-only mechanism (a Postgres trigger on `auth.users`, or an admin-only server action using the Supabase service-role key) that sets `app_metadata.role` from the Prisma `User.role` column — never let the client set it.

2. **Add real authorization inside every admin Server Action and admin page**, not just in middleware. Create `src/lib/auth/require-admin.ts` — a helper that gets the current user, checks `app_metadata.role` is `ADMIN`/`SUPER_ADMIN`, and throws/redirects otherwise. Call it at the top of `createProduct` and `seedCategoriesIfEmpty` (`src/app/(admin)/admin/products/actions.ts`), `updateQuoteStatus` (`src/app/actions/quotes.ts`), `generateInvoiceForOrder` (`src/app/actions/invoices.ts`), and in `src/app/(admin)/layout.tsx`.

3. **Fix the IDOR in order/invoice creation.** In `src/app/actions/orders.ts`, `createOrderFromQuote` must verify `quote.userId` matches the current authenticated user before creating the order. 4. **Sync Supabase Auth with the Prisma `User` table.** Right now `signup()` in `src/app/(auth)/actions.ts` calls `supabase.auth.signUp()` and nothing else — no Prisma `User` row is ever created, and `firstName`/`lastName`/`companyName` from the registration form are silently discarded. 5. **Remove or lock down `src/app/api/seed/route.ts`.** It's a public GET endpoint gated only by a hardcoded `?secret=seed_demo` string with no `NODE_ENV` check, so anyone can trigger it against production. Delete this route and consolidate its logic into `prisma/seed-demo.ts` as a local-only script (run via `npx tsx prisma/seed-demo.ts`), or if an HTTP-triggerable reseed is genuinely needed in staging, gate it behind `process.env.SEED_SECRET` (not a literal) and `process.env.NODE_ENV !== 'production'`.

6. **Fix the Prisma datasource config.** `prisma/schema.prisma`'s `datasource db` block has no `url` field, which is invalid. Add `url = env("DATABASE_URL")` and `directUrl = env("DIRECT_URL")`.
